# FunPerps

Perps for every Pump.fun token. Long the runners, short the rugs. Built on Solana.

- `/` is the website.
- `/app` is the trading dashboard (loaded on demand, so the website never downloads the wallet stack).

## Run it

```bash
npm install
cp .env.example .env   # then fill in VITE_REOWN_PROJECT_ID
npm run dev
```

| Variable | Required | What it does |
|---|---|---|
| `VITE_REOWN_PROJECT_ID` | for wallets | Reown AppKit project ID ([dashboard.reown.com](https://dashboard.reown.com)). Without it the app still shows markets and listings, and explains how to enable wallets. |
| `VITE_SOLANA_RPC_URL` | no | A dedicated Solana mainnet RPC (for example Helius or QuickNode). Defaults to Reown's Solana RPC for your project ID, then PublicNode. |

## Deploy on Vercel

`vercel.json` is ready: Vite build to `dist`, SPA rewrites (so `/app/...` routes load directly), long-cache
headers for hashed assets, basic security headers, and a `www.funperps.xyz` to `funperps.xyz` redirect.

1. Import the repository in Vercel. Framework, build command and output are picked up from `vercel.json`.
2. Add the environment variables (Project Settings, Environment Variables, for Production and Preview):

   | Name | Value | Required |
   |---|---|---|
   | `VITE_REOWN_PROJECT_ID` | your Reown project ID | yes |
   | `VITE_SOLANA_RPC_URL` | a dedicated RPC, e.g. `https://mainnet.helius-rpc.com/?api-key=<key>` | recommended for traffic |

   `VITE_` variables are baked in at build time and are public in the browser bundle. Never put a private key or
   secret here, and use an RPC key that is restricted to your domain. Redeploy after changing them.
3. Domains: add `funperps.xyz` and `www.funperps.xyz` to the project and set the DNS records Vercel shows.
4. In the Reown dashboard, add `funperps.xyz` (and your `*.vercel.app` preview domain if you test there) to the
   project's allowed domains, or the wallet modal will refuse to connect in production.

## SEO

`index.html` carries the title, description, canonical, Open Graph and X card tags, icons, the web manifest and
JSON-LD. `useSeo()` (`src/lib/seo.ts`) updates title, description and canonical per route; Positions and Portfolio
are `noindex`. `public/robots.txt` and `public/sitemap.xml` point at `https://funperps.xyz`. The share image and
app icons are generated by `npm run brand`.

## Dashboard

| Page | What it shows | Data source |
|---|---|---|
| Markets | Every Pump.fun token with a live price: Runners, Rugs, Most traded, New on curve. Paste any mint address to open its market. | GeckoTerminal (`pump-fun` curve and `pumpswap` pools) |
| Market | Candles, live mark price, curve progress or pool stats, spot trades, the order ticket, and your spot balance with a one-click hedge. | GeckoTerminal, DexScreener, Solana RPC |
| Listings | Live feed of Pump.fun launches and graduations to PumpSwap, polled every 30 s. | GeckoTerminal, Solana RPC |
| Positions | Orders the wallet approved, marked to the live price, with time left and cancel. | Signed orders (this browser) |
| Portfolio | SOL margin, the Pump.fun tokens the wallet holds, hedge shortcuts, recent activity. | Solana RPC, DexScreener, GeckoTerminal |

A token counts as a Pump.fun token only if its bonding curve account exists on-chain: the PDA
`["bonding-curve", mint]` owned by the Pump program `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P`. The "pump"
suffix on a mint is not trusted on its own. Curve price and progress are read from that account. Constants live
in `src/app/config.ts`.

| Market | Max |
|---|---|

## Orders

The perps engine is not deployed yet, so no funds move. The order ticket builds the order (side, SOL collateral,
leverage, entry, liquidation price, fee), and the wallet approves it with `signMessage`. The signed order is kept in
this browser per wallet (`src/app/lib/perps/order.ts`) and shows up on Positions.
